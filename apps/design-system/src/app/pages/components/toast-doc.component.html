Casos de Uso

Feedback de Sucesso

Confirmar ações bem-sucedidas como salvamento de dados, envio de formulários ou conclusão de processos.

Exemplo: "Dados salvos com sucesso!"

Notificações de Erro

Alertar usuários sobre erros, falhas de validação ou problemas que requerem atenção imediata.

Exemplo: "Erro ao processar pagamento."

Avisos Importantes

Informar sobre ações potencialmente perigosas ou situações que requerem cautela do usuário.

Exemplo: "Esta ação não pode ser desfeita."
ℹ

Informações Contextuais

Fornecer dicas, atualizações ou informações adicionais que melhoram a experiência do usuário.

Exemplo: "Nova versão disponível."

Notificações Gerais

Comunicar mensagens, lembretes ou atualizações de sistema sem urgência específica.

Exemplo: "Você tem 3 novas mensagens."

Ações Interativas

Incluir botões de ação para permitir resposta rápida do usuário às notificações.

Exemplo: "Nova mensagem" + botão "Ver Agora"

Boas Práticas

Use tipos semânticos apropriados

Escolha o tipo correto (success, error, warning, info) para cada situação.

Mensagens concisas e claras

Mantenha títulos curtos (2-5 palavras) e mensagens diretas ao ponto.

Duração adequada ao conteúdo

Ajuste a duração baseado na quantidade de texto.

Limite toasts simultâneos

Evite empilhar muitos toasts ao mesmo tempo.

Evite toasts para informações críticas

Não use toasts para mensagens que requerem confirmação obrigatória.

Não abuse de toasts automáticos

Evite exibir toasts automaticamente em excesso.

Escolha a variante apropriada

Filled: notificações importantes | Outlined: interfaces clean | Soft: notificações sutis.

Use pauseOnHover para mensagens longas

Sempre ative pauseOnHover quando o toast contém informações importantes.

Acessibilidade

O componente Toast foi desenvolvido seguindo as diretrizes WCAG 2.1:

ARIA Live Regions

Utiliza role="alert" e aria-live="polite" para anunciar toasts.

Navegação por Teclado

Botão de fechar acessível via Tab e acionável com Enter ou Space.

Contraste de Cores

Todas as variantes garantem contraste mínimo de 4.5:1 (WCAG AA).

Indicadores Visuais

Ícones e cores trabalham juntos - nunca use apenas cor para transmitir informação.

Controle de Tempo

Usuários podem pausar toasts ou fechar manualmente (WCAG 2.2.1).

Design Responsivo

Toasts se adaptam a diferentes tamanhos de tela.

Dicas de Implementação Acessível

  • Para toasts com informações críticas, use duration="0"
  • Sempre forneça um título descritivo
  • Teste com leitores de tela (NVDA, JAWS, VoiceOver)
  • Evite toasts que aparecem muito rapidamente em sequência
  • Use showTimestamp quando o timing for importante
  • Garanta que botões de ação tenham labels claros
